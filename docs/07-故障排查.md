# 故障排查

## 先跑这几条

```sh
docker compose ps                                   # 三个都 Up，db 需为 healthy
docker compose logs cloudflared | grep Registered    # 应看到 4 条 Registered tunnel connection
curl -si https://mcp.xxx.dpdns.org/mcp | head -1     # 见下方「判据」
```

### 判据速查

| 现象 | 含义 |
| --- | --- |
| `Registered tunnel connection` × 4 | 隧道与边缘已建立连接，正常 |
| `/mcp` 返回 **401** 且带 `WWW-Authenticate` | Access 保护生效（加了 OAuth 后应如此） |
| `/mcp` 返回 **200** | 未加保护，或 Managed OAuth 被关掉／没保存 |
| Cloudflare 错误 **1033** | 隧道没注册上，请求到了边缘却送不回本机 |
| `SSL handshake failure` / `cert=0` | 边缘没有证书，TLS 在第一层就断了 |

> ⚠️ **不要再用 `/health` 测隧道。**
> 加上 Cloudflare Access 之后，`/health` 和 `/mcp` 一样返回 401，
> 拿它当存活探针会误判。改用上面那条 `grep Registered`。

## 症状 → 原因 → 修法

### 全站打不开，`SSL handshake failure`，`cert=0`

**原因**：Cloudflare 边缘**没有签发证书**。TLS 握手在边缘就失败，请求根本到不了隧道。
和隧道配置无关。

**判据**：`crt.sh` 查该域名返回空；同一个边缘 IP 上的 `cloudflare.com` 正常。

**修法**：面板里 **禁用 Universal SSL → 重新启用**，强制重新下单，状态转为「有效」。

**旁支噪声**：CSR 页面报 `Access to CSRs has not been granted for this zone` 是免费套餐的
entitlement 提示，与证书验证无关，忽略即可。

### 隧道时好时坏，或稳定报 1033

**原因**：Clash 的 fake-IP 模式在 TUN 层劫持了所有 DNS，
`region1.v2.argotunnel.com` 被解析到 `198.18.0.0/15` 伪造网段。
cloudflared 连不上假 IP，隧道注册不上。

**判据**：

```sh
docker compose logs cloudflared | grep -i 'failed to dial'
# Failed to dial a quic connection ... ip=198.18.0.21
```

**修法**（二选一）：

1. **完全退出 Clash 进程**（不是关 Tun），然后
   ```sh
   docker compose restart cloudflared
   ```
2. 在 Clash 配置里加规则让 `argotunnel.com` 直连：
   ```yaml
   - DOMAIN-SUFFIX,argotunnel.com,DIRECT
   ```

**注意**：在容器内指定 `--dns 1.1.1.1`／`8.8.8.8` **无效** —— TUN 层在更底层，换 DNS 服务器绕不过去。

健康时日志应该是 4 条真实边缘 IP：

```
INF Registered tunnel connection connIndex=0 ip=198.41.192.57 location=lax11 protocol=quic
INF Registered tunnel connection connIndex=1 ip=198.41.200.53 location=lax01 protocol=quic
INF Registered tunnel connection connIndex=2 ip=198.41.200.43 location=lax01 protocol=quic
INF Registered tunnel connection connIndex=3 ip=198.41.192.37 location=lax12 protocol=quic
```

### 关掉 Clash 了，但还是不行

**原因**：cloudflared 在**启动时**解析并缓存边缘地址。只退 Clash 不会让它重新解析。

**修法**：`docker compose restart cloudflared`。

### 改了配置，`docker compose up -d` 却没生效

**原因**：Compose 是声明式的。它会比对当前状态与期望状态，
**配置没变、容器在跑**时就判定「已符合期望」，什么都不做 —— 是个 no-op。

| 命令 | 行为 |
| --- | --- |
| `docker compose up -d` | 有变更才重建；**无变更 = no-op** |
| `docker compose restart <服务>` | 无条件重启进程，重新解析 DNS |
| `docker compose up -d --force-recreate` | 无条件重建容器 |

**修法**：凡改了 Clash／DNS／网络环境，或需要重载环境变量，用 `restart`。

### ChatGPT 报 `That account does not have access`

**原因**：Access 策略默认拒绝。只开了 Managed OAuth，但没给应用挂 **Allow 策略**。

**修法**：Access 应用 → Policies → 加一条 `Allow`，选择器用 `Emails` = 你的登录邮箱。

### OAuth 走完了，ChatGPT 却报 `Plugin not found`

**原因**：ChatGPT 侧连接器记录的问题，**不是服务端的问题**。

**修法**：删掉连接器重建。不要去改 mcpjungle 或 Cloudflare 配置。

### ChatGPT 扫不到工具

```sh
docker exec mcpjungle-server /mcpjungle list servers
docker exec mcpjungle-server /mcpjungle list tools
```

两个都空的话，说明注册表被清空了（常见于 `docker compose down -v`），跑：

```sh
./scripts/register.sh
```

### 容器里 `mcpjungle` 命令找不到

```
exec: "mcpjungle": executable file not found in $PATH
```

二进制在**容器根目录** `/mcpjungle`，不在 `$PATH` 里。必须写绝对路径：

```sh
docker exec mcpjungle-server /mcpjungle list servers
```

## 写 compose 时的坑

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `services.x.depends_on must be a array` | `depends_on` 写成了字符串 | 写成列表：`depends_on:` 换行 `  - mcpjungle` |
| `services.mcpjungle must be a mapping` | 留了个空的 `mcpjungle:` 桩键 | 删掉，或补全内容 |
| 环境变量没注入 | `.env` 里写了 `KEY = value` | Compose 会自动 trim 两侧空格，一般没问题；用 `docker compose config` 确认 |
| npx 型 stdio server 起不来 | 用了 `mcpjungle:latest` | 必须用 `latest-stdio` 变体，它才带 node/npx |
